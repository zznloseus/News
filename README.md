## 2026-10-30：引用链识别与补齐修正

- 发文层级区分国务院、部委、省级政府、省级主管部门、市级政府、市级主管部门和县级机构；支持常见部门全称与联合发文。不以转载网站所在地代替发文机关。
- 保留正文引用、文号、层级和防循环校验；国务院→部委、部委→地方主管部门可连接。同名不同版本、跨省冲突、反向层级、媒体报道和自我引用不自动作为上位文件。
- 正文采集约四分之三预算优先用于实施方案、细则和配套措施，四分之一留给最早未处理的普通文件，避免饿死。每小时仍最多12个正文请求候选。
- 每小时新增 `npm run references -- --limit 4`，从正文提取明确引用，先核对本地文件／原文官方链接，再匹配中国政府网公开的历史政策索引。每个引用最多核验3个候选、每轮约90秒上限；受原有robots、限速及超时约束。新增文件进入快照和正文目录，关键词随之更新。
- 同名候选不唯一且没有唯一的原文官方链接时保持待核实；明确官方链接优先于本地同名旧版。文件名、正文和文号必须相符。没有公开索引命中时不会猜测网址或绕过登录/验证码。
- 补齐记录保存在 `data/references.json`，含引用证据、结果及失败原因。成功结果30天后重查，未解决/错误结果至少隔1天重试；出现新版本链接会重新核验。子文件引用的更早上位文件将在后续轮次继续补齐。

- 仅修改上述第2、3点；默认起点选择与页面布局未改。首页进入模块仍可能默认展示没有下游关系的文件，请从已有引用入口或起点选择器查看。

单独运行：`npm run archive -- --limit 24`；`npm run references -- --limit 4`。可以传入 `--data`、`--archives`、`--queue`、`--keywords` 指定补齐输入输出文件。参考队列只属于公开采集数据，不含私人笔记。

- **发现首页**：政府来源／媒体关注／全部三种口径共用日期与来源筛选；六领域可多选取并集，并保留其他／未归类入口。默认合并时间流按同文去重，另可切换分领域双栏，各栏保留选词和页码。每页8份文件。

- **中央—地方阅读**：使用实际已收录节点、明确正文引用、引用段落和来源版本。主题相近的候选单独列出，没有证据时显示空状态或未关联文件。引用不等于落实成效；同文转载、媒体报道不构成政府落实关系。不根据发布网站推断实际发文机关或地区。

## 关键词如何更新

每小时采集完成后重新生成 `data/keywords.json`，和 `data/snapshot.json` 一起提交和发布。专业词表统一明确同义词；保守分词和连续词组规则发现词表外新词。预置词在当前范围须涉及至少2份文件，自动新词须涉及至少3份去重文件、2个来源；不能保证发现所有新词。

同标题、同年份的转载合并，采用同文最早有效发布日期。同一文件中重复提及只计一次。近期统计与领域列表排除缺失、无效和未来日期；原始记录保留在快照中。统计随来源、阶段、政策类型和日期变化，自由搜索和本栏选词只缩小列表。结果反映本站已收录标题的提及情况，领域颜色不表示支持力度。

“新”表示本站最近7天首次识别并达到门槛；首批历史初始化不标新。新词观察历史持久保存。索引缺失、损坏或与快照不一致时，构建／浏览器从当前快照重新分析。可用 `npm run keywords` 单独生成；词表在 `lib/keyword-config.mjs`，修改提取算法时递增 `KEYWORD_ENGINE_VERSION`。

## 原有功能与部署

可独立部署的国家政策观察网站。页面由 GitHub Pages 提供，GitHub Actions 每小时采集公开来源、合并历史数据并重新发布。保留搜索、领域／来源／阶段／日期筛选、收藏、官方原文跳转、CSV 导出、来源状态和采集记录。

项目配置 **90 个配置来源（88个启用）**：58 个中央部门、官方媒体与专业入口，加大陆31个省级政府及新疆生产建设兵团。配置数量与实际采集成功数量分别显示；不承诺所有站点均可抓取。已附带从原网站公开接口导出的真实历史数据，来源状态与时间一并保留。

## 部署到 GitHub

1. 创建一个 GitHub 仓库，把本项目**解压后的文件**放在仓库根目录。必须包含 `.github/workflows/`、`data/snapshot.json`、`package.json` 和 `package-lock.json`。不要只上传整个 ZIP 文件，也不要多嵌套一层项目目录。
2. 进入仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
3. 在 **Actions** 中找到 **Update policies and deploy Pages**，选择 **Run workflow**，使用默认分支运行。`collect` 保持勾选会先采集全部来源；取消勾选可以先用附带数据快速发布。
4. 运行完成后，打开部署记录或仓库 Pages 设置中返回的正式网址。项目仓库通常是 `https://你的用户名.github.io/仓库名/`，个人主页仓库也支持根路径。

后续代码推送到默认分支会触发采集和发布。只更新 Markdown 或 `data/` 不会再触发一次重复发布；每小时工作流会在自身运行中提交数据并完成部署。

工作流使用 GitHub 自动提供的 `GITHUB_TOKEN`，不需要添加 OpenAI 密钥、Sites 令牌或外部数据库凭据。如果数据提交步骤提示权限不足，请检查仓库／组织的 Actions 写入限制、默认分支保护规则，以及是否允许工作流提交 `data/snapshot.json`。受组织策略限制时，需要仓库管理员调整相应规则。

## 每小时更新

- 计划时间：**每小时更新一次，在每个整点触发**，对应工作流中的 `0 * * * *`。北京时间同样是每个整点。
- GitHub 定时任务可能排队延迟，整点是计划触发时间，不是保证完成时间。
- 可以随时在 Actions 页面手动运行；不依赖个人电脑保持开机。
- 各来源独立记录结果。失败、超时、动态页面和访问限制不会清空历史条目。
- 所有来源均失败时，仍保留历史并发布失败状态，同时在 Actions 日志中显示警告。
- 定时工作流只在默认分支运行。若 GitHub 因长期仓库无活动等原因停用定时任务，需要在 Actions 页面重新启用。
- 原有网站及其更新计划不会因为下载本项目而改变；确认 GitHub 版本稳定后，再决定是否停用旧站点。

## 本地运行

需要 Node.js **22.13.0或更新版本**。

```bash
npm ci
npm run dev
```

开发服务器会打印本地地址。正式构建及验证：

```bash
npm test
npm run check
npm run build
npm run verify
```

`npm run verify` 会启动一个临时的纯静态服务，检查根路径与仓库子路径的页面、脚本、样式、图标和真实数据是否可读，同时检查静态站点不依赖旧后台接口。

手动采集全部来源：

```bash
npm run collect
```

仅验证两个来源，并把结果写入独立文件：

```bash
npm run collect -- --sources miit,nda --data work/check.json
```

采集后默认尝试最多12份政府正文文字留存；可用 `npm run archive -- --limit 12` 单独补存，或 `--archive-limit 0` 关闭该轮正文尝试。

采集默认并发6个来源，每个来源总时间上限45秒。可用 `--concurrency 4` 或 `--timeout 30000` 调整。每个来源每轮最多收录70条公开索引，对部分条目提取简短简介；这不是全站全文或完整历史归档。

## 项目结构

```text
.github/workflows/   每小时更新、部署，以及只读的拉取请求检查
src/                React 界面、样式、浏览器数据读取与 CSV 下载
lib/sources.mjs      90个来源的域名、分类与公开列表地址
lib/crawler.mjs      网页／公开接口解析、域名限制、日期和阶段识别
lib/dataset.mjs      去重合并、筛选、统计及导出逻辑
lib/collector.mjs    有界并发、数据校验及原子写入
data/snapshot.json  随网站发布的公开历史数据和来源状态
scripts/            采集、构建、静态部署验证和公开数据导入工具
tests/              采集、历史保留、检索、CSV和子路径相关测试
dist/               构建产物；自动生成，不提交到源码仓库
```

## 数据与隐私

- 页面直接读取本站的 `data/snapshot.json`、`data/keywords.json` 和 `data/archives.json`，搜索和导出在访问者浏览器中执行，无需后台 API 或数据库。
- 收藏保存在当前浏览器。换到新的域名后，浏览器不会自动迁移旧域名的本地收藏；公开政策数据已随项目提供。
- 标题、简介和地址作为公开索引保留。第四版领域按标题关键词辅助归类，来源身份单独分组，阶段按标题自动识别，只用于辅助检索。发布日期可能由页面或地址识别，缺失时保持“日期未标注”。政策效力和正文请核对官方原文。
- 采集遵守来源访问限制和可读取的 robots 规则，不绕过验证码或登录，不把采集失败显示为“没有新政策”。不同运行地区的网络可达性不同，GitHub 上的成功来源数可能与其他托管环境不同。
- 数据会持续积累。若长期增长到较大的单文件规模，可进一步做历史分片或归档；当前版本保留全部已收集条目和最近365轮记录。

## 改动来源或更新时间

编辑 `lib/sources.mjs` 可以修改来源的 `feeds`、机构主题分类、身份映射和允许域名。新增接口应验证原文地址、返回结构以及实际发布日期。修改来源后，推送到默认分支并手动运行一次采集。

编辑 `.github/workflows/update-and-deploy.yml` 的 `schedule` 可以修改时间；表达式使用 UTC。并发控制禁止两个部署任务互相取消或同时覆盖数据。若数据推送遇到默认分支已更新而失败，确认最新代码后重新运行即可，不要强制推送。
